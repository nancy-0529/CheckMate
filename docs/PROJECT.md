# 專案脈絡

這份文件說明 CheckMate 是什麼專題、為什麼這樣做、做了哪些東西，以及過程中的取捨。想看產品本身的定義，請讀 [Product Brief](product/product-brief.md)；這裡補的是「這個專案是怎麼走到現在的」。

## 背景

CheckMate 是 **2026 AI Practitioner Program 第 5 組**的專題。

原始命題（完整內容見 [Original Challenge](product/original-challenge.md)）：設計一個 **AI 費用單據初審 Agent**，讀取費用申請與憑證，依企業規範完成初審，並讓財務人員快速分辨哪些案件可以繼續、哪些需要補件或人工介入。Demo 必須使用 5–10 筆模擬案件，涵蓋正常、重複申報、超出上限、缺附件、金額不一致，且全部為 Mock Data。

## 我們的切入點

現有費用審查有兩個極端：全靠人工逐筆檢查（慢、標準因人而異），或純規則自動化（抓得到超額與缺件，看不到情境與規則外的風險）。直接把 AI 丟進去又會帶來「判斷難預測、難追溯」的問題。

CheckMate 的主張是：**把 AI 的判斷能力放進一套可控制、可追溯、可逐步授權的審查層**，疊在既有 ERP／費用系統之上，不要求企業換系統。

幾個核心設計決定：

- **建議與動作分開**：Agent 給出「建議通過／補件／人工審核」，但能不能自動執行，由企業授權範圍與控制條件決定，不是由模型的信心決定。
- **只做初審**：不做最終核准、入帳、付款、稅務申報。範圍越窄，越能把「可控」這件事講清楚。
- **留下決策紀錄**：每次 Agent 判斷與人工覆寫都可追溯，作為日後調整規範與授權邊界的依據。

## 已知取捨

- **原型的審查結果是預置的**：8 筆案件的分析結果事先寫好，沒有串接 OCR、LLM 或後端。專題目標是驗證產品流程與資訊架構，不是工程實作。展場版（`booth/`）則有一個簡化的規則引擎（`booth/src/engine.ts`），能依企業規範即時計算結果。
- **嘗試過又移除的功能**：曾在原型加入「單一案件即時初審」流程，實際看過畫面後判斷會讓人誤以為系統壞掉，因此移除。完整說明見 [開發交接](development/handoff.md)。
- **全部資料皆為模擬**：不含任何真實個資、財務或企業資料。
