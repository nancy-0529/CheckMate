# CheckMate 開發交接

## 目前版本
React 19 + TypeScript + Vite，純前端，8 筆完整預置案例。開發前先讀 CLAUDE.md、Original Challenge、Product Scope 與 specs/。

- 深海軍藍風格，列表與右側詳情並排，可展開詳情。
- 依待處理／待補件／已完成初審／全部分流；初審建議是獨立篩選。
- 支援單筆模擬處理、建議通過的批次完成，以及人工確認原因與歷史檢視。
- 工作台的完整初審結果皆為預置資料，SVG 憑證全是模擬素材。
- E-01 v1 金額比對（`app/src/features/review/amount-check.ts`）已實作為純函式並有單元測試，目前無使用者可見入口（見下方「已嘗試並回退」）。
- 所有操作只在記憶體內；刷新清除。沒有後端、登入權限、LLM、OCR、寄信、ERP 或付款串接。

## 已嘗試並回退：單一案件的即時初審流程
曾把 E-01 v1 整合進一筆新增案件（EXP-2026-010）的即時流程：待初審 → 開始初審 → 讀取憑證／模擬擷取欄位 → 真算金額比對 → 只更新佐證比對一格，其餘面向掛「尚未執行」Finding，案件整體維持「建議人工審核」（不發明新狀態）。畫面與邏輯都做完且測試通過，但這筆案件在案件列表中長期顯示「初審結果：尚未開始初審」，實際看過畫面後判斷這會被誤認為系統錯誤而非「即時執行」的展示重點，體驗上不成立，已於 Demo Day 準備階段移除（含 EXP-2026-009，同為多餘的「正常案件」情境，一併移除回到 8 筆）。`runAmountCheck`／`case-review.ts` 已刪除；`checkAmount`／`amount-check.ts` 保留，未來若要再示範即時執行，需要更好的呈現方式（例如不要讓「還沒審完」的案件長期停留在已審完案件的同一份列表）。

## 這一輪保留下來的改善（跟上面那次嘗試無關，對全部案件都適用）
- 案件詳情的「審查結果與比對」改成一行一項的檢查清單（圖示＋一句結論＋關鍵數字直接顯示，不用展開才看到數字），「處理建議」改成依建議上色的卡片。
- 憑證預覽改成預設收合的 `<details>`（「憑證比對」可點開），避免詳情頁一次攤開太長看不到全貌；展開詳情時會與檢查清單並排兩欄（原本這組 CSS Grid 已存在但未接上，這次一併接上，修掉展開後版面被拉寬變空洞的問題）。
- 案件列表：案件編號、申報項目在前並凍結、可左右滑動；新增「初審結果」欄（一句話摘要，取自案件既有的 Finding），跟「初審建議」都加上主色圖示標示為 Agent 產出；申報項目／初審結果超過兩行以刪節號截斷，Hover 顯示完整內容；處理狀態欄只在「全部」分頁顯示且改為 Chip 樣式；展開詳情時列表不再整個隱藏，改為變窄並保留凍結欄與捲動。
- 完成初審的提示改為純文字、約 2.5 秒自動消失，不需手動關閉，也不再提供「查看案件」按鈕。
- 已用 Playwright 手動跑過關鍵路徑（案件移出待處理列表、展開詳情兩欄排版、憑證比對展開收合），畫面與既有互動一致，無 console error。

## 協作限制
- 目前變更尚未 commit／push。另一個工具若在同一個本機資料夾工作，可直接接手；只 clone GitHub 不會取得未推送內容。
- 不要 git reset、覆蓋或丟棄現有未提交修改。
- 使用者希望控制用量：一次一個最小可驗證步驟；產品行為與 UX 取捨先確認，實作細節自主。
- 不重新設計整個介面；既有文件不代表所有產品決策均已定案。
- 不使用真實個資或公司財務資料。

## 主要入口
- app/src/App.tsx：工作台、詳情與處理對話框。
- app/src/data/cases.ts：模擬案件、費用明細及憑證關係。
- app/src/features/review/workbench.ts：搜尋、處理進度、批次操作。
- app/src/features/review/amount-check.ts：精確金額比較（E-01 v1 純函式），目前無使用者可見入口。
- specs/amount-check.md：目前單項檢查的範圍與限制。

## 驗證與部署
（以下指令在 `app/` 資料夾內執行；repo 結構見根目錄 README。）

```bash
npm install
npm test
npm run build
npm run lint
npm run dev
```

部署目標 Vercel，SPA 路由透過 app/vercel.json 回到 index.html。Vercel CLI 可部署目前工作目錄，不必先 commit／push。部署網址供操作及 review，不提供開發原始碼；Claude 接手需要本機工作目錄或另行授權的原始碼交付。
